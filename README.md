# MIS-StudentPortal

Starter monorepo untuk Student Portal & MIS.

## Arsitektur

- `app/fe` — Next.js + NextAuth
- `gateway` — Express API Gateway
- `app/be/student-api` — external/student-facing API + PostgreSQL
- `app/be/internal-api` — internal MIS API + PostgreSQL
- `keycloak` — IAM/SSO
- `keycloak-db` — PostgreSQL khusus Keycloak
- `packages/*` — shared types/config/logger

## Flow

### Login
Browser → Frontend → NextAuth → Gateway (`auth.localhost:4000`) → Keycloak → callback NextAuth → `/dashboard`

### Business API
Frontend → Gateway (`api.localhost:4000`) → Student API / Internal API → DB masing-masing

## Aturan penting

- Business API **tidak** dibuat di Next.js `app/api`, kecuali endpoint NextAuth.
- Gateway tidak memiliki ORM/database bisnis.
- `student-api` hanya terhubung ke `student-db`.
- `internal-api` hanya terhubung ke `internal-db`.
- Keycloak memakai database PostgreSQL sendiri.
- Queue/domain events nantinya dipublish backend, bukan Gateway.

## Local hostname
Biasanya `*.localhost` resolve otomatis. Jika `auth.localhost` atau `api.localhost` tidak resolve di Windows, tambahkan ke hosts:

```text
127.0.0.1 auth.localhost
127.0.0.1 api.localhost
```

## Menjalankan

1. Siapkan file konfigurasi lokal dari template; jangan commit file `.env`:

```text
.env.example                         -> .env
app/be/internal-api/.env.example     -> app/be/internal-api/.env
app/be/student-api/.env.example      -> app/be/student-api/.env
keycloak/.env.example                -> keycloak/.env
```

Root `.env` dipakai Compose untuk interpolation/orchestration seperti published ports, database bootstrap, dan credential awal database container. Backend runtime mengambil koneksi dari `.env` masing-masing service. Samakan database name/user/password di konfigurasi API dengan database container development yang dibuat oleh root Compose environment. `keycloak/.env` mengatur runtime Keycloak; password koneksinya harus sama dengan password Keycloak DB.

2. Install dependency root/workspaces:

```bash
npm install
```

3. Validasi Compose:

```bash
docker compose config
```

4. Jalankan:

```bash
docker compose up --build
```

5. Cek:

- Frontend: http://localhost:3000
- Gateway health: http://api.localhost:4000/health
- Keycloak Admin: http://localhost:8080/admin

## Setelah infrastructure hidup

Buat user test di realm `mis-student-portal`, beri salah satu role, lalu login lewat frontend.

Migration business DB dijalankan dengan:

```bash
npm run migrate
```

> `.env` dalam starter ini hanya untuk local development. Jangan reuse secret-nya di environment bersama atau production.

## Package lock

`package-lock.json` is generated by the first successful `npm install` at the repository root and should then be committed. The starter does not include a fabricated lock file.

## Migration in Docker

After the core containers are running:

```bash
npm run migrate:student
npm run migrate:internal
```

The root scripts execute Sequelize CLI inside the running backend containers, so the migration receives the same DB environment used by the service.

Development/test seed data (tidak membuat user atau subject Keycloak):

```bash
npm run seed:internal
npm run seed:student
```

Seeder menolak berjalan ketika `NODE_ENV=production`.

The student API, internal API, and Keycloak each use a separate PostgreSQL database service. The internal MIS and Keycloak PostgreSQL data use new Docker volumes so the old SQL Server volumes remain untouched.

## System error monitoring

The `system-monitor` container checks the API gateway, internal API and its database, student API and its database, and Keycloak every 30 seconds. Two consecutive failed checks open an incident and trigger an email. Repeated API 5xx responses are grouped by service and endpoint; five within five minutes trigger an alert, with a ten-minute cooldown.

Set `DEVELOPER_SUPPORT_EMAIL` in the root `.env` to the Developer Support mailbox. SMTP settings are read from `app/be/internal-api/.env` (`MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_ENCRYPTION`, and `MAIL_FROM_ADDRESS`). Without a recipient or SMTP settings, incidents remain in container logs and email delivery is skipped.

Backend errors use the response shape `{ "error": { "code": "...", "message": "...", "requestId": "..." } }`. The request ID is also returned in the `x-request-id` response header and is included in structured logs.
